# ACCEPTANCE_TESTS v3.0

1. 首页只选择阵型，不显示或提交预算、身价、价格池。
2. 运行时选秀白名单正好900人：传奇156、球星344、球员400；原始1402人数据仍保留。
3. 每局服务器内部生成11张池券；每张独立按4/11传奇、4/11球星、3/11球员随机，没有保底或上限。
4. 客户端在揭晓前不能看到本轮或后续池券，也不能指定池类型。
5. 每轮最多返回5名同池候选；当前候选未选时不能刷新。
6. 所有候选至少兼容当前阵型的一个空缺槽位，界面和接口均不提供指定位置次数。
7. 选人请求必须同时提交球员ID和空缺槽位ID；服务端原子完成签入与落位。
8. 只选11人，没有暂存未分配选人、替补、换人、红黄牌和伤病。
9. 球员卡直接展示位置、FM式八维数值和带标签雷达图，不显示身价。
10. 刷新恢复当前局；旧预算存档保留但提示重新开始。
11. 选满11人且每个首发槽合法后才能锁定阵容；战术在赛季前设置并锁定。
12. 玩家随机替代25/26英超20队中的一队，与其余19队完成38轮主客场双循环。
13. 赛季逐轮显示具体对手、比分和进球人员，可自动滚动或跳过到结果。
14. 完赛展示成绩、积分、排名和真实队内球员数据；重新游玩必须重选阵容。
15. 公开接口不泄露 `fmAttributes`、`ability`、价格模型、预算、身价或未揭晓池券。
16. 未来PVP双方共享相同11轮池券序列和顺序，但各自候选独立随机。
17. PVP扑救必须显示门将向落点移动，并区分抱住、扑出场内和扑出底线；未进球不得让足球进入球网。
18. PVP必须能产生低频一脚传球/射门，以及有明确原因和站位的犯规、任意球、角球、点球和越位进球无效片段。
19. PVP常规时间平局后不进行加时赛，直接逐球播放点球大战并以点球比分决定胜负。
