# DRAFT_POOLS v3.0

## 三个选秀池

运行时只允许 `config/draft-pools.json` 白名单中的900名球员进入选秀。原始1402人数据不删除，仍可用于维护和重新筛选。

| 池 | 人数 | 每轮权重 |
|---|---:|---:|
| 传奇池 | 156 | 4/11 |
| 球星池 | 344 | 4/11 |
| 球员池 | 400 | 3/11 |

传奇全部保留；球星池由原球星池和筛选后的强援组成；球员池从原主力、轮换和基础池中筛选。筛选结果可在 `data/manual/draft-player-curation.csv` 审查，重建命令为：

```powershell
node scripts/build-draft-pools.mjs
```

## 池券与候选规则

- 每局服务器独立生成11张池券，每张分别按4/11、4/11、3/11随机；没有保底和上限，因此允许0个或11个传奇池。
- 每轮先揭晓池券，再从对应池随机展示5名候选；本轮必须选择1名，不能刷新候选。
- 每名候选至少能胜任当前阵型的一个空缺首发位置，避免11人前出现无合法位置的死局。
- 选中球员时必须同时指定空缺首发槽位，选人和落位由服务端原子完成。
- 不再提供指定位置次数；每轮候选由当前池券和阵型剩余空位共同约束。
- 选满11人后停止出人。没有预算、身价、购买能力或比赛加成。

未来PVP由房间生成并共享同一条11轮池券序列和轮次顺序；双方各自独立随机候选球员。
