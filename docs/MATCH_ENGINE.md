# MATCH_ENGINE v2.0

## 当前模型

- 玩家固定使用赛季开始前锁定的11名首发和一套战术，所有人每场踢满90分钟。
- 当前版本没有替补、换人、红黄牌、伤病、停赛或跨场体能。
- 每场先把11名球员的FM原始属性、位置熟练度、当场状态、首发化学和战术聚合为进攻/中场/防守/门将四项球队强度。
- 双方球队强度、主场优势和受控随机性共同生成预期进球，再以泊松分布生成比分。
- 比分确定后，按真实球员位置与底层能力分配进球、助攻和赛后评分；AI进球事件使用`config/opponent-rosters.json`中的真实名单。

## 球员能力参与方式

- 选秀卡的八维只用于展示，比赛不会直接拿八维代替FM属性。
- 射手权重同时考虑射门相关FM属性、实际位置、出场时间；中锋和边锋明显高于中卫与后腰。
- 助攻权重同时考虑传球/视野等FM属性与位置；前腰、中场和边路球员更高。
- 最佳/第二/其他登记位置分别使用100%/95%/90%，未登记位置不能放入槽位。
- 每场状态按`config/balance-config.json`重新抽取，默认不会跨场延续。

## 球队与比分

- 玩家球队强度公式、预期进球和战术参数都集中在`config/gameplay-config.json`；选秀池不提供隐藏比赛加成。
- AI球队基础四维、阵型与战术来自`config/opponents.json`；每场AI状态波动来自`gameplay-config.json`。
- 2025/26英超20队进行主客场双循环：每队38场，全联赛380场。
- 积分规则为胜3、平1、负0；依次比较积分、净胜球、进球数、相互比赛积分、相互比赛客场进球和稳定抽签键。

## 比赛事件和统计

- 战况时间线只生成双方的进球和助攻事件；0比0或没有进球的球队不会产生虚假事件。
- 队内球员统计：出场、首发、分钟、进球、助攻、平均评分。
- 门将额外累计失球、零封和扑救。
- 评分由进球、助攻、赛果、当场状态、零封、失球和小幅随机波动共同计算，不直接等于球员能力。

## 有意保留的简化

当前不是逐次传球/射门的完整FM级事件引擎，而是“FM属性聚合强度 → 预期进球与比分 → 真实人员事件分配”的轻量赛季模型。这样可以快速播放38轮，同时让阵容质量、位置、战术和球员职责真实参与结果。
